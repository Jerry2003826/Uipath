# Coding Agent Evidence

PermitOps uses coding agents as assistants for scenario generation, repair drafting, documentation, and evidence summarization. Coding agents are not trusted authorities. Their outputs must be reviewed, tested, and connected to deterministic evidence.

## Evidence Principles

- Preserve the original prompt or task given to the coding agent.
- Preserve the generated output or a stable reference to it.
- Record whether the output affected tests, repair candidates, documentation, or demo materials.
- Record the human review decision.
- Link any accepted output to deterministic oracle results and Test Cloud evidence.
- Never treat a coding-agent patch or generated scenario as approved until it passes the PermitOps certification loop.

## Evidence Log Schema

Recommended fields:

- `entry_id`
- `timestamp`
- `agent_role`
- `task`
- `input_summary`
- `output_summary`
- `files_or_artifacts_touched`
- `human_review_status`
- `deterministic_oracle_status`
- `test_cloud_reference`
- `evidence_hash`
- `notes`

## Review Checklist

Before accepting coding-agent output into the PermitOps evidence chain:

- Confirm the output is in scope for the requested task.
- Confirm it does not create a new trust decision by itself.
- Confirm generated scenarios map to explicit policy rules.
- Confirm any repair candidate is re-tested.
- Confirm Test Cloud evidence exists for certification claims.
- Confirm Action Center approval exists before license issuance.
- Confirm license metadata includes `compiler_rules_hash`, `evidence_hash`, and `license_hash`.
